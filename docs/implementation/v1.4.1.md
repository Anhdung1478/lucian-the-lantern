## Context
The V1.3.0 code review (artifact "Lantern code review") still has open items after V1.3.1 and V1.4. The user picked these for **V1.4.1**: 1, 13, 12, 14, 11, 15, 17, 18, 21, 22, 23, 24. The big one is **bug 1**: crafting is free and a legendary sells for 70% of its price, so crafting and then selling makes gold. The fix is to move crafting out of the backpack and onto the merchant, and charge a fee. The rest are small bugs.

## Decisions and how I read the request
- **Bug 1 (crafting):**
  - **One Craft tab.** The merchant's **Boots** tab becomes a **Craft** tab, and it does both kinds of craft:
    - `[fragment] + [fragment] → legendary`. The fee is the legendary's cost minus the two fragments' costs. For example, Muramana is 2900 − 400 − 400 = 2100.
    - `[boots] + [fragment] → upgraded boots`. The fee is the boots' existing `upgrade_cost`. Boots have no cost of their own, so the subtraction rule can't apply to them.
  - **The exploit closes for every recipe.** Crafting plus selling now returns 0.7 × cost − fee, and that is always less than selling the two fragments: the gap is −0.3 × (cost − fragments).
  - **No backpack crafting.** Dropping a fragment on its partner just swaps them, and the craft pop-up is deleted.
  - **The recipe table stays, and now also shows in shop mode**, since crafting happens there. At 1920 px the backpack starts at about x = 408 and the table ends at 316, so it fits.
- **Economy (your answer):** the fee makes the game harder. The bots measure that before and after the fee, and the report gives the numbers. There is **no gold retune**.
- **Bug 13 (potions):** the backpack's right-click **Use** button is removed. Potions are drunk only with keys 7 and 8, which already check `can_act()`. `Lucian.use_item` gets the same guard, so no other path can skip it.
- **Bug 12 (6-5):**
  - Thresh's Lantern Souls get the boss wave's scaling: 1.7× at wave 8, up from 1.0×. That raises their HP from 338 to 574 and their damage from 38.5 to 65.5.
  - Then a bot check. The goal is to keep 6-5 about as hard as it is now, because the V1.3 pass tuned it with the souls at 1.0×. If it gets clearly harder, I tune only Dark Passage's knobs (`PASSAGE_SOULS` 3, `PASSAGE_CAP` 6, `PASSAGE_COOLDOWN` 16 s), which touch only Thresh's summons.
- **Bug 11:** a saved `ending_seen` flag. The End shows on any 6-5 clear until it has been seen. An old save with no flag counts as not seen, so a save hit by this bug gets The End on its next 6-5 clear. A save that already saw it gets it once more.
- **Bug 18:** skill cards show the cooldown with ability haste applied, and they rebuild while hovered when haste or rank changes. The review also mentions buff timers freezing on hovered cards; that is **not** in scope.
- **Bug 23:** the 1-1 replay panel says "2 waves + boss wave" while its note says "No boss on replays". A cleared 1-1 really does spawn only 2 waves, so the fix is the wording: "2 waves".
- **Bug 24:** Reset is refused when nothing would come back (only free levels bought). The question now names the refund.

## Steps (one commit each)

### Fix 1: Crafting moves to the merchant, with a fee
**Core**
- `src/core/item_catalog.gd`:
  - `craft(a, b) -> ItemData` tries `boots_upgrade(a, b)`, then `boots_upgrade(b, a)`, then `combine(a, b)`.
  - `craft_fee(a, b) -> int` is the boots' `upgrade_cost`, or `maxi(made.cost - a.cost - b.cost, 0)` for a legendary, or 0 when nothing is made.
- `src/core/inventory.gd`:
  - Remove `Drop.CRAFT`, `craft_result()` and the `craft_ready` parameter of `drop_outcome` and `apply_drop`. Update every caller: `backpack_screen`, `tests/tools/autoplay.gd`, `tests/tools/screenshot.gd`, and the tests.
  - Add `craft_into(keep, use_up, made)`: cell `keep` gets `made` (count 1), `use_up` is emptied, and `changed` is emitted once. The boots cell works as `keep` too.
- `src/core/shop.gd`:
  - Replace `upgrade_result` / `upgrade_boots` with `craft_result(first, second)`, `craft_fee(first, second)` and `craft(first, second) -> Result`.
  - The two indexes must be different and unlocked, and both cells must hold something.
  - The fee is spent first; `NO_GOLD` changes nothing.
  - A boots result keeps the boots cell and uses up the fragment's cell. A legendary keeps the **first** input's cell and empties the second.
  - `Result`: `NO_RECIPE` replaces `NOT_UPGRADABLE` and `NO_BOOTS`.

**UI**
- `src/ui/shop/upgrade_slot.gd` becomes `craft_slot.gd` (`git mv`; class `CraftSlot`, with `Kind { INPUT, RESULT }`).
  - Both inputs take a fragment or the boots.
  - The placeholder reads "ITEM".
  - The tooltip note reads "Drag a fragment or your boots here".
  - Run `--import` after the rename so the class cache is rebuilt.
- `src/ui/shop/shop_panel.gd`:
  - `TAB_NAMES = ["Items", "Potions", "Craft"]` and `CRAFT_TAB := 2`.
  - The page is `[input] + [input] → [result]`, then the fee (red when you can't afford it), then a **Craft** button.
  - Note line:
    - "Drag in two fragments, or your boots and a fragment."
    - "Now drag in a fragment."
    - "X are fully upgraded."
    - "That fragment doesn't upgrade X."
    - "No legendary is made from X and Y."
    - "X + Y → Z"
  - New hint text, and a `NO_RECIPE` message.
  - Rename the accessors: `first_input()`, `second_input()`, `craft_preview()`.
- `src/ui/backpack/backpack_screen.gd`:
  - Delete `CRAFT_HOLD`, `_craft_time`, `_craft_popup` and `_update_craft_popup`. Delete `src/ui/backpack/craft_popup.gd` and its `.uid`.
  - `UPGRADE_BOOTS` / `UPGRADE_FRAGMENT` become `CRAFT_FIRST` / `CRAFT_SECOND`, and `upgrade_boots()` becomes `craft()` (it plays `craft`).
  - The recipe table stays visible in `open_shop`.
  - Update the header comment.
- `src/ui/tooltip/tooltip_card.gd`:
  - Fragment footer: "Craft it with another fragment at the merchant."
  - Legendary footer: "Recipe: X + Y + N gold at the merchant", using `catalog.craft_fee`.
  - Boots footer: "Craft at the merchant with …".

**Tools**
- `autoplay.gd` `_craft()` takes the `Shop` and crafts through `shop.craft` while gold ≥ fee + 100. It runs **before** buying, as a player would.
- `screenshot.gd`: the `scenario_craft` and `boots_shop` scenarios become a `craft_shop` scenario (a legendary and a boots craft).

**Tests**
- Update:
  - `test_inventory` (drop the craft tests and the third argument)
  - `test_backpack_drag` (no craft pop-up; a fragment dropped on its partner swaps)
  - `test_boots` and `test_boot_passives` (`shop.craft`, `NO_RECIPE`)
  - `test_shop_drag` (the Craft tab end to end; the recipe table is shown in shop mode)
  - `test_item_catalog`
- Add:
  - The fee for every recipe equals cost − parts, and is > 0.
  - Crafting then selling never beats selling the parts, for all 33 recipes.
  - `NO_GOLD` leaves both cells as they were.
  - The legendary lands in the first input's cell.
  - The boots can go in either input.
  - Locked or identical cells are refused.

### Fix 12: Thresh's souls at boss-wave strength; 6-5 balance check
- `src/stage/stage.gd:453`: pass `wave` to `spawn_enemy(id, arena.boss_point, wave)`.
  - Bosses ignore wave scaling (`EnemyData.hp_scale` returns 1 for bosses), and story rewards don't use the wave (`stage.gd:762`). So only the summons change.
- **Tests (`test_thresh_final`):**
  - The story boss's `wave` is the boss wave (8).
  - A soul from Dark Passage has 150 × 2.25 × 1.7 HP (× difficulty) and 22 × 1.75 × 1.7 damage.
  - Thresh's own HP is unchanged.
- **Balance check.** Run 6-5 alone on Normal, skilled and average, 3 runs each, before and after this fix:
  ```
  -- <tier> 10 6-5 6-5 <blue> <orange>
  ```
  - The blue and orange are whatever the Step 0 bot held when it reached 6-5.
  - Compare the tries per run and the `lantern_soul` row of the "taken by" breakdown.
  - If the fix makes it clearly harder (the median tries go up by more than 1, or the average bot gets walled), lower `PASSAGE_SOULS` to 2 or raise `PASSAGE_COOLDOWN`. Rerun and record the numbers in the report.

### Fix 18: Skill cards show hasted cooldowns and refresh while hovered
- `src/ui/tooltip/tooltip_card.gd:108`:
  - Each rank's value is `snappedf(Cooldown.hasted(v, haste), 0.1)`, where `haste = lucian.stats.ability_haste + lucian.passives.skill_haste(slot)`.
  - When haste is above 0, a dim "(N ability haste)" follows.
- `src/ui/hud/skill_slot.gd`: new `tooltip_version()` returns `[haste, rank]`.
- `src/ui/tooltip/hover_tip.gd`:
  - While a card is shown, if the source has `tooltip_version()` and its value changed, rebuild the card.
  - No blink: the old card stays until the new one is placed.
- **Tests:**
  - `test_tooltips`: the card text with Blue buff shows 20 haste and the hasted numbers.
  - A new `test_hover_tip`: a hovered skill card rebuilds when haste changes and stays the same object when nothing changes.

### Fix 21: A broken save slot warns and can only be overwritten
- `src/core/save_game.gd`:
  - `slot_broken(n)`: a file exists, but neither the main file nor the backup reads.
  - `_read(file, quiet := false)`, so the slot list doesn't spam warnings.
  - `load_slot` returns `bool`.
- `src/ui/menu/slot_list.gd`: a broken slot reads "Slot N · can't be read" in the error color.
- `src/ui/title/title_screen.gd` `_on_picked`:
  - **Loading** a broken slot opens `confirm.confirm("Slot N can't be read, so it can't be loaded. You can only overwrite it with a new game.", "New game", show_difficulty.bind(slot))`.
  - **New game** on a broken slot uses the existing overwrite question.
  - The gear menu's Save as copy already asks before overwriting.
- **Tests:**
  - `test_save_game`: `slot_broken`, a broken main file with a good backup isn't broken, and `load_slot` returns false.
  - `test_title_screen`: the label, Load on a broken slot warns and never loads, and New game from the warning reaches the difficulty page.

### Fix 22: settings.json goes through a temp file
