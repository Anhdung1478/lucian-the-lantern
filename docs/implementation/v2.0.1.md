# V2.0.1: a language setting, English or Vietnamese — Implementation Plan

> **Project:** `E:\Project\lucian-the-latern` (Godot 4.7.2 game).
> **Status:** asked for by the user on 2026-11-13 ("add language select, with only English and Vietnam. Translate the game to Vietnam when Vietnam language selected."), built the same day (report: `docs/report/v2.0.1.md`).
> **Branch:** `v2.0.1` off `main` (`727f954`, V2.0.0).

## Context
The game was English only, with its texts written straight into the code and the data resources: about 780 strings in 89 scripts and about 325 text fields in the data. V2.0.1 adds a language setting with two choices, English and Vietnamese, and a Vietnamese text for everything a player reads. No rule and no number changed.

## Decisions
- **Mechanism:** Godot's `TranslationServer` with gettext files, behind one function, `Lang.t(text)`. English stays the source text in the code; Vietnamese is looked up by that text. The contract for code and for translators is `docs/translation.md`.
- **Choosing the language:** Settings → Gameplay → Language, and two buttons at the title screen's top right, each language named in itself so a player who cannot read the language in use still finds theirs. The setting is `language` (`en` or `vi`), saved with the other settings for every save slot, and starts as English.
- **Switching:** the title and the main screen are built again in the new language at once, with Settings open on the tab it was on. In a stage the choice is locked: a stage keeps the language it started in. That keeps every screen whole: no half-translated HUD after a switch.
- **Font:** the engine's built-in font (Open Sans SemiBold) has every Vietnamese letter; checked letter by letter before the work started. No font was added.
- **Names:** League of Legends names follow the Vietnamese client. A glossary of 292 names was checked against Riot's own Vietnamese data files: 206 are the client's wording, 26 are the players' common wording (minions and jungle monsters), 60 are the game's own things and translated naturally. It is `locale/glossary_vi.md`.
- **Left in English:** the game's name on the title, champions' names, key names and mouse labels, "FPS" and "VSync", and the debug tables.
- **AD and AP** read SMCK and SMPT in Vietnamese, as Vietnamese players write them.

## As built

### The groundwork
- `src/core/lang.gd` (`Lang`): `t(text)`, `code()`, `use(code)`, the two languages and their own names. `Lang.probe` (tests only) makes `t()` answer with `mark(text)`: every plain letter swapped for its fullwidth form, values and tags kept, so a text on a built screen that still has plain letters never went through `t()`.
- `GameSettings`: `language` in `DEFAULTS`, refused when a file holds an unknown code; `apply_language()`, part of `apply_engine()`.
- `SettingsScreen`: the Language row first on the Gameplay tab; `language_locked` (set by a stage) greys it out with a note; `open(at)` and `tab`.
- `LanguagePicker` (`src/ui/settings/language_picker.gd`): the title's two buttons.
- `Game`: on `changed(&"language")` it applies the language and, once the click is over, builds the title or the main screen again and opens Settings on the tab it was on (`TitleScreen.open_settings(at)`, `MainScreen.open_settings(at)`).
- `project.godot`: `[internationalization]` lists the five files; the fallback is `en`.
- `tests/lang_probe.gd` (`LangProbe`): the texts a script holds (`literals`, `missing_in`), the data resources' texts (`data_texts`, `missing_data`), the plain texts on a built screen (`plain_texts`), and what a translation must keep (`values`, `tags`).
- `tests/tools/screenshot.gd`: `SCREENSHOT_LANG=vi` takes every scenario in that language; it finds buttons by their text in the language in use.

### The texts
- `locale/vi/common.po` (222): every `display_name` and `effect_name` of the data, the stat names and the words two parts share.
- `locale/vi/items.po` (167), `stage.po` (184), `main.po` (213), `shell.po` (112): one file per part of the game. 898 entries in all, each with a comment saying where it shows and what its values are.
- `locale/untranslated/*.txt` (94 lines): texts the scan finds that stay as they are: key and mouse labels, the game's name, audio bus names, a few formats with no words.
- 538 calls in 86 scripts go through `Lang.t()`. Sentences that the code joined from pieces are one format each now (the boots' footer, potion texts, the Act 1 tips, the tree's reset question, level requirements, wave counts), since a sentence cannot be translated in pieces. English output is unchanged.
- Two places compared a text to decide something and now use a flag instead: the merchant's sell-price message (`ShopPanel._selling`), and the result card's rows, which keep English keys for their icons and translate when drawn.

### How it was built
- One name glossary first (a Sonnet worker with web search, against the client's data files), then the groundwork, then four Sonnet workers in parallel worktrees, one per part, each with its own `.po`, its own list of untranslated texts and its own test.
- An Opus reviewer then read all 898 entries against their English: 121 changed, for meaning (the gear menu called the title screen "the main screen"), for one term per English term (save slot, rank, modifier, buff against effect), for natural wording and spoken dialogue, and for fit.
- 223 screenshots of 69 scenarios were taken in Vietnamese and read by three Sonnet workers for English left on screen, text that did not fit, broken letters and odd wording. What they found is fixed: see the report.

### Tests
- `test_lang.gd` (14): the setting, the picker, the lock in a stage, the rebuild by the Game, the marks.
- `test_translations.gd` (11): the files are the ones the project lists and they load; no translation is empty, breaks its English's values or tags or edge spaces, or differs between two files; every text in `src/` (but the debug tables) and every data text has a Vietnamese or is listed as left in English.
- `test_lang_items.gd`, `test_lang_stage.gd`, `test_lang_main.gd`, `test_lang_shell.gd` (45): each part's screens, built with the probe on, show no plain text; direct checks in Vietnamese.

## Still open
- A stage cannot change language while it is played.
- Vietnamese is longer than English in most places. The spots still tight are listed in the report.
- The names marked "likely" in the glossary (minions, jungle monsters, the dragons) are the players' wording, not confirmed against the client.
- The screenshot tool's `act3_result` scenario fails in both languages (it expects the drake after three waves; 3-2 has six since V2.0).
