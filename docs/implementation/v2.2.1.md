# V2.2.1: Web build for itch.io — Implementation Plan

> **Project:** `E:\Project\lucian-the-lantern` (Godot 4.7.2 game).
> **Status:** Implemented on 2026-11-25 (uncommitted, awaiting user review). Phase 1 confirmed Option A (time-sliced music rendering), WebGL2 Compatibility rendering with zero JS/shader errors, and `build/web/index.html` single-threaded export.
> **Branch:** `v2.2.1` off `main` (`b5b89c1`, V2.2.0).
> **Target version:** `2.2.1`: an HTML5 build on **itch.io**, next to the Windows `.zip`, which is rebuilt as 2.2.1 too.

---

## Context

*Lucian: The Lantern* ships only as an unsigned Windows `.exe` in a `.zip`. Players have to download it, unzip it and click through Windows SmartScreen before they can play.

The game is pure GDScript and 2D, with ~2.2 MB of assets, so a Godot Web (WASM) build is a good fit. Most of the download will be the engine itself (tens of MB), not the assets. The desktop build stays the main version; the Web build lets people play in a desktop browser with no install.

No gameplay rule, stat, stage or price changes. Every Web-only change is behind one check, `GameSettings.web` (see 2.1), which tests can set to run the Web code paths headless.

---

## Decisions

1. **Hosting:** itch.io HTML5 embed, on the same page as the Windows `.zip`. The page is free (no payments, no "pay what you want") and carries the README's Riot Games disclaimer.
2. **Single-threaded export** (`variant/thread_support=false`): no `SharedArrayBuffer`, no COOP/COEP headers, works in the itch.io iframe in Chrome, Edge and Firefox.
3. **Renderer:** desktop stays on Forward+ (`project.godot` sets no renderer, so Forward+ is the default). The Web build is always on the Compatibility renderer (WebGL2). This is a renderer switch, not just a shader check: Phase 1 previews it natively first (`--rendering-method gl_compatibility`).
4. **Skill rank-up is Shift + skill key, on every platform.** Ctrl + skill keeps working as before (desktop players know it), but the hint only names Shift. Why:
   - Browsers keep Ctrl+W (close tab) and Ctrl+R (reload) for themselves.
   - Alt is not safe either: on Windows, Alt+E opens the Chrome/Edge menu and Firefox's Edit menu, and Alt alone shows Firefox's menu bar.
   - Nothing in the game uses Shift today, and key bindings already drop every modifier (`GameSettings._clean`), so no binding can clash.
   - One hint and one translation for every platform; no Web-only text.
   - The HUD's "+" on a skill already ranks it up with the mouse.
5. **Camera on Web:** `StageCamera.mode` starts as `Mode.FOLLOW`, and the mouse is not confined. Browsers can't confine the cursor, so edge panning breaks when it leaves the canvas. `Y` still switches to free-cam and `Space` still centers.
6. **A menu button in the stage HUD (Web only).** In browser fullscreen, ESC leaves fullscreen and never reaches the game, so without a button there is no way to pause. The button opens the same menu as ESC (`open_menu`). The other uses of ESC already have a mouse path: right-click cancels a cast, a click elsewhere cancels a binding.
7. **No Exit on Web.** `get_tree().quit()` freezes the canvas, so the Exit buttons are hidden on the title, the gear menu and the in-stage menu.
8. **Graphics settings on Web:** a **Fullscreen** toggle, **Quality** and **Show FPS**. Window mode, Resolution, VSync and FPS cap are hidden; their stored values are left alone. Fullscreen is never saved or applied at start, because browsers allow it only from a click. The toggle always shows the browser's real state: when Settings opens, and when the player leaves fullscreen with ESC or with itch.io's own button while Settings is open. `GameSettings.owns_window` is set to false on Web, which already skips all window sizing and window-mode calls.
9. **Default Quality on Web:** Medium (2× MSAA) for a fresh Web settings file. Phase 1 confirms it or moves it to High or Low.
10. **Music on Web: time-sliced rendering (Option A) by default.** The pieces are rendered on the main thread across frames, within a per-frame budget, while the old piece plays on (as it does now). Desktop keeps `WorkerThreadPool`. This keeps one source for the music (`score.gd`) and adds no files.
    - **Fallback, Option B (pre-baked `.ogg`):** used only if Phase 1 shows that Option A, at a 4 ms per-frame budget, takes over ~10 s to finish Act 6 (the longest piece) or makes the audio crackle. The score is 16-bit stereo at 22,050 Hz with ~30 s loops plus a 3 s tail, so 7 pieces × 5 layers is ~19 minutes of audio, **about 7 MB** as Ogg Vorbis.
11. **Saving on Web.** Closing a tab never sends the window-close notification that asks "Save before leaving?" (`game.gd:53`), and Exit is hidden. Today the game saves on its own only at Start and when a stage ends, so tree, shop and skin purchases would be lost.
    - **Autosave on the main screen:** every real change to `SaveGame` (its `changed` signal) saves the slot, at most once per frame.
    - **A leave prompt:** while something is unsaved, or a stage is open, the page asks the browser for its standard "Leave site? Changes you made may not be saved" prompt. Browsers don't allow custom text or a Save button there, and the game gets no time to save while the tab closes. The prompt is a safety net against an accidental close; the autosave is what keeps progress.
    - Progress inside a stage is not autosaved. On desktop, a crash in a stage loses that stage too, and saving mid-stage would change what leaving means.
12. **Translations:** every new player-facing string goes through `Lang.t()` and gets a Vietnamese entry in `locale/vi/*.po`. The Fullscreen toggle reuses the existing `"Fullscreen"` entry. The browser's leave prompt is the browser's own text and needs none.

## Phased plan

### Phase 1 — Web export prototype and benchmark

Goal: run an unchanged single-threaded Web build in a browser and record what breaks or lags before any fix is written.

1. **Native preview of the Web renderer:** run the desktop game with `--rendering-method gl_compatibility`. Compare it with Forward+ on: the menu blur (`menu_backdrop.gd` / `.gdshader`: `BackBufferCopy` and `hint_screen_texture`), the additive glows (`shot_glow.gd`, `tree_node_view.gd`), `ghost_image.gdshader`, `grey_icon.gdshader`, and 2D MSAA at each Quality.
2. **Install the Godot 4.7.2 Web export templates** into `%APPDATA%\Godot\export_templates\4.7.2.stable\`.
3. **Add a `"Web"` preset** to `export_presets.cfg`:
   - `platform="Web"`, `export_path="build/web/index.html"`
   - `exclude_filter="tests/*, docs/*, addons/gut/*"`
   - `variant/thread_support=false`
4. **Export and serve it locally** (`python -m http.server` in `build/web/`, or Godot's remote debug), in Chrome or Edge and in Firefox. Test both a plain page and inside an `<iframe>`, to match itch.io.
5. **Benchmark and audit checklist**, all written down before Phase 2:
   - **Music render:** in this build the pool has no worker threads, so the unchanged render runs on the main thread. Measure the stall on the title (the theme) and on entering each act, and the time of each layer of Act 6. These numbers set Option A's chunk size, or trigger Option B (Decision 10).
   - **Audio crackle:** music (`AudioStreamSynchronized`) can't use the browser's direct sample playback, so it is likely mixed on the main thread. Listen in a heavy fight and during a render. Check that SFX still play with their random pitch in sample playback.
   - **Audio unlock:** the theme starts cleanly after the first click on the title.
   - **SFX first plays:** check whether the lazy `Sfx.stream()` synthesis stutters on the first hits.
   - **Performance:** a heavy fight and a late Endless wave on High, Medium and Low. Confirm or change the Web default Quality (Decision 9).
   - **Keys:** Shift / Ctrl / Alt + Q, W, E, R; Ctrl + C (stats panel); ESC in a window and in browser fullscreen; right-click move and attack; wheel zoom. Check that the page never scrolls and that no context menu opens on the canvas.
   - **Saves:** a write, a backup and a rename (`user://save_slot_*.json`) survive a hard reload. Save and then close the tab at once: is the save still there when the page reopens?
   - **Leave prompt:** a hand-written `beforeunload` listener in the exported `index.html` shows the browser prompt inside the iframe, in each browser, after one click on the canvas.
   - **Fullscreen from an in-game click:** Godot handles the toggle in its own frame, not inside the browser's click handler. Godot's Web layer bridges this for `WINDOW_MODE_FULLSCREEN`. Confirm with a temporary button calling `window_set_mode(WINDOW_MODE_FULLSCREEN)`, in Chrome or Edge and in Firefox, plain and inside an iframe with `allowfullscreen`. If the browser blocks it, the Web Graphics page drops the toggle and the itch.io page points to its own Fullscreen button.
   - **Size:** the total export size and the first-load time.

> **Phase 1 gate:** review the findings. Confirm Option A (or move to Option B), the Web default Quality, and that the leave prompt works inside an iframe. If it doesn't, the autosave alone stays and the itch.io note says so.

### Phase 2 — Web compatibility

Goal: fix what Phase 1 found and apply the Decisions without changing desktop behavior beyond the Shift rank-up.

#### 2.1 Platform flag
- `src/core/game_settings.gd`: `static var web := OS.has_feature("web")`, next to `owns_window`. At start on Web, `owns_window` is set to false. Tests set `GameSettings.web = true` and reset it in `after_each`.
- Anything that calls the browser (`JavaScriptBridge`) checks `OS.has_feature("web")` itself, not `GameSettings.web`, so headless tests that set the flag never reach it.

#### 2.2 Music and audio
- **`src/audio/music.gd`:** when `GameSettings.web`, `_render()` starts a time-sliced render instead of the `WorkerThreadPool` group task. `_process` advances it within `RENDER_BUDGET_MS` (start at 4, adjust from Phase 1) and hands the finished stream to `_collect_render()`'s cache path. `_exit_tree()` drops an unfinished Web render instead of waiting for it.
- **`src/audio/score.gd`:** split the render into steps that can stop and resume: one layer per step if Phase 1 shows each layer fits the budget, otherwise a resumable layer render that adds a few notes per step (`_add_note` already works note by note). Desktop keeps calling `render_layer()` whole. Both paths must produce the same samples.
- **Audio unlock:** the theme starts or resumes on the first click.
- **`src/audio/sfx.gd`:** only if Phase 1 showed first-hit stutter: warm up the common combat sounds at stage load, a few per frame.
- **If Option B:**
  - `tests/tools/bake_music.gd` writes `assets/music/piece_<n>_layer_<m>.ogg`.
  - A test fails when `score.gd` changes without a re-bake (a hash of the score's constants stored next to the files).
  - Check the loops for clicks at the seam.
  - The Windows preset excludes `assets/music/*`, so desktop keeps synthesizing.

#### 2.3 Controls and camera
- **`src/lucian/lucian_controller.gd` `_key_input()`:** Shift or Ctrl + a skill key ranks it up (`shift_pressed or ctrl_pressed`), on every platform. Update the comment.
- **`CONTROLS_HINT`** (`settings_screen.gd:81`): "Shift + a skill key ranks it up". Update its Vietnamese entry (`shell.po:405`, a new msgid since the sentence changes).
- **`src/stage/stage.gd`:** don't confine the mouse when `GameSettings.web`.
- **`src/stage/stage_camera.gd`:** start in `Mode.FOLLOW` when `GameSettings.web`.
- **The HUD menu button** (`src/ui/hud/hud.gd`): Web only, styled with the existing `UiStyle` tokens. A click does what ESC does (`open_menu`). Hover note: "Menu (ESC)", with its Vietnamese entry.
  - **Where:** the top-right corner itself, at `MARGIN`. The gold plate (`_build_gold()`) moves left by the button's width plus a gap. The plate grows leftward as the gold gets more digits, so the button must not sit on its left edge, where it would move. (The FPS label is top-left and can't overlap.)
  - **Check at 1280 × 720,** in English and Vietnamese: the button and the plate stay clear of the boss bar, the wave preview and the tip banner. Cutscenes hide the HUD, so the cutscene's Skip button (also top right) never meets the menu button.

#### 2.4 UI, settings and Exit
- **Hide Exit when `GameSettings.web`:**
  - `src/ui/title/title_screen.gd:241` (`Exit game`)
  - `src/ui/main/gear_menu.gd:113` (`Exit the game`)
  - `src/ui/menu/game_menu.gd:87` (`Exit the game`)
- **`src/core/game_settings.gd`:**
  - `apply_display()` skips VSync and the FPS cap on Web (window mode is already skipped through `owns_window`), but still sets MSAA from Quality.
  - `window_mode` is never applied or saved on Web.
  - A fresh Web settings file gets `quality = "medium"` (or what Phase 1 chose).
- **`src/ui/settings/settings_screen.gd` `_build_graphics()`:** on Web, the page holds:
  - Fullscreen: a toggle that calls `DisplayServer.window_set_mode(WINDOW_MODE_FULLSCREEN / WINDOW_MODE_WINDOWED)` in its click handler;
  - Quality;
  - Show FPS.
  
  Reset to defaults leaves Fullscreen as it is.
- **Fullscreen toggle sync:** `_build_graphics()` runs once, in `setup()`, so the page is not rebuilt when Settings opens. `_sync_fullscreen()` sets the toggle from `DisplayServer.window_get_mode()` with `set_pressed_no_signal()`. It runs:
  - in `open()`;
  - while Settings is open, on the viewport's `size_changed` (the browser resizes the canvas when fullscreen starts or ends).
  
  A refresh never calls `window_set_mode()` again.

#### 2.5 Saves and the leave prompt
- **Unsaved state, in `SaveGame`:** an `unsaved` flag. `changed` alone can't drive it, because `_apply()` also emits `changed` when a slot is loaded (`save_game.gd:446`), and `reset()` emits it when a new game starts.
  - A `changed` handler sets `unsaved = true`.
  - Once their own `changed` has fired, `load_slot()`, `reset()` and `start_new()` set it back to false, and so does a successful `save()`.
  - So a slot that was just loaded or created is never unsaved.
  - Leaving is unsafe while `unsaved` is true or a stage is open.
- **Autosave, in `src/main/game.gd`:** when `GameSettings.web` and the screen is the main screen, `SaveGame.changed` queues one deferred check for the end of the frame (a `_save_queued` flag and `call_deferred`).
  - The check saves only if `unsaved` is still true then. A purchase that changes several things saves once, and a load, which clears `unsaved` before the frame ends, saves nothing.
  - A failed autosave shows a red toast ("Could not save.", with its Vietnamese entry). It does not block play.
- **New `src/core/leave_guard.gd`:** the Web-only bridge.
  - At start (only if `OS.has_feature("web")`), one `JavaScriptBridge.eval` adds a `beforeunload` listener that calls `preventDefault()` while `window.lucianUnsafe` is true.
  - The Game sets that value whenever the unsafe state changes.
  - The rule (unsaved or in a stage) is a static function, so tests can check it without a browser.
- **`src/core/save_game.gd`:** fix any storage problem found in Phase 1.

#### 2.6 Tests (GUT)
- Shift + skill and Ctrl + skill rank up; Shift alone with a skill key does not cast twice.
- Web: Exit is hidden on the title, the gear menu and the game menu; it stays on desktop.
- Web: the Graphics page holds only Fullscreen, Quality and Show FPS; desktop is unchanged.
- Web: the camera starts in `FOLLOW`; desktop starts in `FREE`.
- Web: the stage HUD has the menu button and pressing it opens the menu; desktop has none. The button and the gold plate don't overlap, with 1 and with 99,999 gold.
- Web: the Fullscreen toggle follows the window mode when Settings opens and on `size_changed`, without calling `window_set_mode()`.
- Web music: no `WorkerThreadPool` task is started, and a time-sliced render produces the same samples as `render_layer()` for one layer of each piece.
- `SaveGame.unsaved`: true after a change, false after a save, false after `load_slot()`, `reset()` and `start_new()`. The leave rule: unsafe when unsaved or in a stage.
- Web autosave: one purchase on the main screen writes the slot once; loading a slot writes nothing; a change inside a stage doesn't save.
- `test_translations.gd` passes with no missing entries.

## Risks and watchouts

| Risk | Mitigation |
|---|---|
| The Compatibility renderer draws the menu blur or the glows differently, or slowly with MSAA | Native preview first (Phase 1.1); on Web, fall back to a plain darkening or lower MSAA. |
| Music crackles: the music is mixed on the main thread, which the time-sliced render also uses | A per-frame budget measured in Phase 1; Option B if the budget can't be met. |
| The leave prompt doesn't show inside the itch.io iframe, or the player clicks Leave | The autosave is the real protection; the prompt is only a safety net. |
| A save written just before the tab closes doesn't reach the browser's storage | Checked in Phase 1 (save, then close at once). The autosave runs right after each change, not at close. |
| Autosave rotates the backup after every change, so the backup is only one change old | The same meaning as a manual save today; accepted. |
| itch.io's iframe steals focus or scrolls on the wheel | Tested in an iframe in Phase 1; if needed, handle the wheel and the context menu in a custom HTML shell. |
| Private windows or cleared site data wipe saves | Said on the itch.io page; a save export/import can follow if players ask. |
| Ctrl + W or Ctrl + R pressed out of habit closes or reloads the tab | The hint names Shift only; autosave and the leave prompt limit the loss. |
