> **Status:** asked for by the user on 2026-11-13 ("run another round to improve the UI for all the game"), built. **Final verdict: OK** (the judge's fourth review, r4, 2026-11-13).
> **Branch:** `v2.1.0` off `main` (`ed79c5a`, V2.0.1), with the Stageshow skill committed on top (`6abea8b`).

## Context
The user asked for another round to improve the UI of every screen, using the Stageshow skill, with sub-agents chosen by difficulty and a Fable 5.2 judge reviewing until it says OK. Two features came with it:
- **Attack-move mode:** one key (A by default) gives the order alone, and a setting in Settings → Controls picks between that and the old A-then-click.
- **Right-click on an enemy attacks it.**

No stage rule, number or price changed.

## Decisions
- **The skill:** Benji Taylor's Stageshow skill was imported to `.claude/skills/stageshow`. It builds faux product UI in React and CSS, and the game is Godot, so its code was not used; its rules (one set of tokens, motion that is short and soft and has an end state, spacing on one grid, type steps, nothing popping in) were applied to the game's UI.
- **A kit first:** the motion, the numbers and the spacing became shared code before any screen was touched (`UiMotion`, `CountLabel`, `SlideHighlight`, the `UiStyle` tokens and helpers, and `HoverTip`'s anchor, placing and fades). See `ui_design.md`, "The UI kit (V2.1)". `UiMotion.off()` makes every call land on its end state at once, in headless runs, on Low quality and in screenshots, so tests and bots see no difference.
- **Attack-move:** the setting `attack_move_mode` is `normal` (default: A arms it, a left-click gives the order) or `quick` (A alone gives it, at the cursor). It is a dropdown on the Attack-move row of Controls, and Reset to defaults puts it back. The Act 1 tip has a Quick wording.
- **Right-click on an enemy** attacks it. It does not start the hold-to-move, since the hold would re-issue a walk and overwrite the attack. A merchant is still visited and the ground still walked.
- **Tips** wait while a wave banner is showing.

## How it was run
- **Judge reviews:** a Fable 5.2 judge read the screens and wrote a review per round (`r1.md`, `r2.md`, `r3.md`, ...), each with MUST and SHOULD items. A round fixes them, and the next review checks the fixes.
- **Order:** the kit first, then five areas in parallel worktrees, one worker each: the HUD; the backpack and the merchant; the stage overlays (result, pick, banner, End, captions); the main screen (Journey, tree, skins, toast); the shell (title, menus, Settings). The controls were a sixth, small item. Each area was cherry-picked onto `v2.1.0` in order.
- **Models:** by difficulty, as in the earlier rounds: Sonnet for specified work, Opus where judgment was the work.
- **Docs:** this plan, `ui_design.md`, `main_screen.md`, the README, the game design doc, `act1_the_loss.md` and `translation.md` were updated after the code.

## As built
- **HUD:** larger item, potion and boots cells on one grid; corner tabs for cost, key and stack; cards hang above the bar; the top is one stack that moves; the gold counts.
- **Backpack and merchant:** one strip on the backpack's columns, the sell slot in the merchant's foot, tabs on a shared track, larger potion rows, a count of open cells in place of chains.
- **Stage overlays:** the result arrives in beats with counting stats, the essences are the plate's second read, the recap sits in the right column, pick cards fit their text.
- **Main screen:** sections swap with a crossfade, the tree's panel leads with "Levels bought" and ends with a list of the branch's known nodes, the Journey panel reads top to bottom.
- **Shell:** the logo is pinned and the title's pages are a fixed slot; slot rows are three parts and one width; menus, pop-ups and Settings open as overlays; one column template on Controls.
- **Tests and tools:** tests for the pinned logo, the parted rows, the question card and the right-click; `training_setup` prints the Refresh button's text from `ShopPanel.refresh_text()`; the `act3_result` scenario now clears all six waves of 3-2 (it expected three, so it failed in V2.0.1).
- **Translation:** the Vietnamese texts for new lines are in the `.po` files; "Quick" (attack-move mode) is "Nhanh" and "Normal" is "Thường" for both difficulty and attack-move mode (`docs/translation.md`).
